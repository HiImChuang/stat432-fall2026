library(RLT)

set.seed(123)
# Predictors and True model = X1 + X3 + X5
testX <- mvrnorm(n = 200, mu = rep(0, 5), Sigma = rep(0.3, 25) + 0.7 *    diag(5)) %>% matrix(nrow = 200, ncol = 5)
colnames(testX) <- paste0("X", 1:5)
testY <- rowSums(testX[,c("X1", "X3", "X5")]) + rnorm(nrow(testX))

# 9 Tuning settings
settings <- rbind(expand.grid(
    mtry = 3,
    nodesize = c(1, 5, 10, 20, 30)
), expand.grid(
    mtry = c(1, 2, 4, 5),
    nodesize = 10
))
setting_names <- apply(settings, 1, function(row) paste0("mtry", row["mtry"], "_nodesize", row["nodesize"]))

# 100 predictions * 9 tuning settings * 200 testing points
rep = 100
results <- array(NA, dim = c(nrow(testX), nrow(settings), rep))
dimnames(results) <- list(NULL, setting_names, NULL)

# Loop over the tuning settings and store the results
for (i in seq_len(rep)){

    X <- mvrnorm(n = 200, mu = rep(0, 5), Sigma = rep(0.3, 25) + 0.7 *    diag(5)) %>% matrix(nrow = 200, ncol = 5)
    colnames(X) <- paste0("X", 1:5)
    Y <- rowSums(X[,c("X1", "X3", "X5")]) + rnorm(nrow(X))

    for (s in seq_along(setting_names)) {
        mtry <- settings[s, "mtry"]
        nodesize <- settings[s, "nodesize"]
        # Fit a model with the current settings (example using linear regression)
        fit <- RLT(
            X, Y, model = "regression",
            ntrees = 500, mtry = mtry, nmin = nodesize,
            resample.prob = 1, resample.replace = TRUE
            )
        results[, s, i] <- predict(fit, testX)$Prediction
    }
}

# Calculate bias squared and variance
bias_variance <- apply(results, MARGIN = 2, function(x) {
    bias_squared <- (rowMeans(x) - testY)^2
    variance <- rowSums((x - rowMeans(x))^2) / ncol(x)
    c(bias_squared = bias_squared, variance = variance)
})

mean_bias <- colMeans(bias_variance[paste0("bias_squared", 1:200), ])
mean_variance <- colMeans(bias_variance[paste0("variance", 1:200), ])

# Reporting table

) %>% separate_wider_regex(setting, c("mtry", mtry = "\\d+", "_nodesize", nodesize = "\\d+")) %>% mutate(mtry = factor(mtry), nodesize = factor(nodesize))

1b

As the node size increases, the variance of the predictions tends to decrease, while the bias may increase slightly. This is because larger node sizes lead to more stable predictions but can also result in less flexible models. The phenomenon is similar to KNN, when node size is large, the prediction of a point is using more neighbors, which averages out the predictions and reduces variance but may increase bias.

When using large mtry value, the variance of the predictions tends to increase, while the bias may decrease. This is because considering more features at each split allows the model to choose the best feature for splitting, as a result, the model becomes more flexible and can capture more complex relationships in the training set, which may or may not be truly meaningful relationships that will also show up in testing data. On the other hand, with low mtry value, the model is more constrained in its feature selection, which may cause true features to be overlooked, leading to higher bias.

If the bootstrap sample is 100 instead of 200 for each tree, the difference between each bootstrap sample may be larger than they are now. If we stick to the same mtry and node size, the variance is expected to be larger. As a result, I expect larger node size would be preferable.
